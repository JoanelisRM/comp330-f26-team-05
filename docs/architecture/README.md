# Architecture

This directory contains the overall structure and organization of the system to define its components and how they'll interact.

Architecture should be used to decide responsibilities, interfaces, data ownership, dependencies, failure boundaries, and decision memory, 
and have little to do about actual code. Strong architecture will help the team change, test, review, and explain the system with little issue. 

## Structure

Any decisions added here should remain consistent with what has been decided in 

- requirements;
- acceptance criteria;
- scope;
- estimates;
- task plan;
- risk register;
